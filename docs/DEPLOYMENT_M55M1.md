# Deploying the FOMO Person Counter on the Nuvoton M55M1

Target board: **Nuvoton NuMicro M55M1 series** (Cortex-M55 + Helium MVE +
**Ethos-U55-256** NPU + on-board camera headers).

This guide is the bridge between the trained Keras FOMO model in this repo
and a working firmware build on the M55M1. We have already verified the
model compiles **100% to NPU** at **19.6 ms / inference** (~50 FPS) using the
exact memory mode and accelerator config Nuvoton ships in their YOLO sample.

---

## 1. Pipeline overview

```
         keras_fomo/runs/fomo/model_int8.tflite          (trained, 2.7 MB)
                         │
                         │  scripts/compile_vela.sh  (Ethos-U vela 3.10.0)
                         ▼
         keras_fomo/runs/fomo/vela/model_int8_vela.tflite (2.5 MB, NPU-ready)
                         │
                         │  scripts/gen_model_header.py
                         ▼
         model_int8_vela.cc  +  model_int8_vela.h        (C array for firmware)
                         │
                         │  drop into Nuvoton TFLM sample
                         ▼
                   firmware .elf / .bin
                         │
                         │  Nu-Link / NuMicro ICP / J-Link
                         ▼
                    M55M1 board
```

Three artefacts the firmware needs from us:

1. `model_int8_vela.cc` / `.h` — the model embedded as a C array.
2. `firmware/fomo_postprocess/{fomo_postprocess.c,fomo_postprocess.h}` —
   heatmap → count, NMS, threshold.
3. **Quantization parameters** (already verified on the trained model):

   | Tensor | shape           | dtype | scale                  | zero_point |
   | ------ | --------------- | ----- | ---------------------- | ---------- |
   | input  | `(1,192,192,3)` | int8  | `0.007843137718737125` | `-1`       |
   | output | `(1,6,6,1)`     | int8  | `0.00390625`           | `-128`     |

   Hard-code these in the firmware, or read them at runtime from the
   `TfLiteTensor` (preferred — see step 4).

## 2. Repeatable conversion (host machine)

Run from the repo root. Everything needed to go from trained model to a
NPU-ready C array, every time you retrain:

```bash
# (a) Vela compile for Ethos-U55-256 / Shared_Sram / Size-optimised
bash scripts/compile_vela.sh keras_fomo/runs/fomo/model_int8.tflite

# (b) Generate the C array + header + model-info externs
python scripts/gen_model_header.py \
    keras_fomo/runs/fomo/vela/model_int8_vela.tflite \
    --image-size 192 --channels 3 --num-classes 1 --grid-size 6
```

Outputs:

```
keras_fomo/runs/fomo/vela/
├── model_int8_vela.tflite     # binary (also useful for python verification)
├── model_int8_vela.cc         # <-- embed in firmware
└── model_int8_vela.h          # <-- include in firmware
```

The generated `.cc` places the model in section `.rodata.tflm_model`
aligned to 16 bytes (the alignment Ethos-U expects). It also defines the
following externs the Nuvoton sample code references:

```c
extern const int originalImageSize;       // 192
extern const int channelsImageDisplayed;  // 3
extern const int numClasses;              // 1
extern const int gridSize;                // 6
```

## 3. Verify the post-processing on the host **before** flashing

We ship a self-contained C unit test that exercises every code path in
`fomo_postprocess.c`. This catches NMS / threshold / dequant bugs without a
single flash cycle:

```bash
gcc -std=c11 -O2 -Wall -Wextra \
    firmware/fomo_postprocess/fomo_postprocess.c \
    firmware/fomo_postprocess/test_fomo_postprocess.c \
    -o /tmp/test_fomo -lm
/tmp/test_fomo
```

Expect 5 PASS lines. Re-run any time you change the post-processing.

## 4. Firmware integration (Nuvoton TFLM sample)

The private `ML_M55M1_SampleCode` repo is already vendored at
`ML_M55M1_SampleCode-master/`. A complete drop-in sample lives at:

```
ML_M55M1_SampleCode-master/M55M1BSP-3.01.003/SampleCode/NuEdgeWise/
    ObjectDetection_FOMO/
```

It was generated by adapting the official `ObjectDetection_YOLOv8n`
sample. Both already share:

- camera capture into a `tflite_input_buffer`,
- LCD/UART output of the prediction,
- `ethos-u` driver init, TFLM interpreter, tensor arena sized for an
  Ethos-U55-256 model.

### 4.1 What is already done

The `ObjectDetection_FOMO` sample is a complete fork of `ObjectDetection_YOLOv8n` with:

| Concern              | Done?  | Where                                                   |
| -------------------- | ------ | ------------------------------------------------------- |
| Op resolver          | yes    | `Model/FOMOModel.cpp` -- registers only `EthosU`        |
| Model load from SD   | yes    | `main.cpp::PrepareModelToHyperRAM` reads `0:\\model_int8_vela.tflite` |
| Camera 192x192 RGB888| yes    | `main.cpp::imlib_nvt_scale` to input tensor (unchanged from YOLO) |
| Pixel-to-int8 shift  | yes    | `main.cpp` line ~516: `signed_req_data[i] = (int8_t)req_data[i] - 128;` |
| Post-processing      | yes    | `FOMOPostProcessing.cpp` -- dequant + 3x3 NMS + threshold |
| Count overlay on LCD | yes    | `main.cpp::DrawFomoOverlay` -- count text + active-cell boxes |
| KEIL project         | yes    | `KEIL/ObjectDetection.uvprojx` updated to reference FOMO sources |
| Vela model included  | yes    | `Model/model_int8_vela.tflite` (2.5 MB, copy to SD)     |

The tensor-arena macro `ACTIVATION_BUF_SZ=0x00100000` (1 MB) defined in
the KEIL project is plenty for our model -- vela reports the resident
arena requirement is well under that.

### 4.2 Build and flash

```text
1. Run install.py at the repo root once to expand the M55M1 BSP.
2. Open
       ML_M55M1_SampleCode-master/M55M1BSP-3.01.003/SampleCode/NuEdgeWise/
       ObjectDetection_FOMO/KEIL/ObjectDetection.uvprojx
   in Keil uVision5.
3. Build (F7). It links against the same TFLM/CMSIS-NN/openmv libs the
   YOLO sample uses -- no extra setup.
4. Connect Nu-Link, flash via the IDE or NuMicro ICP Programming Tool.
5. Copy
       ML_M55M1_SampleCode-master/M55M1BSP-3.01.003/SampleCode/NuEdgeWise/
       ObjectDetection_FOMO/Model/model_int8_vela.tflite
   to the SD-card root.
6. Insert SD, power on the board, open a 115200-baud serial terminal.
```

### 4.3 Tuning at runtime

To retune without rebuilding the model: edit the single constant
`FOMO_THRESHOLD` in `main.cpp` (default `0.30f`, which was best-on-val).
Lower -> more sensitive, more false positives. Higher -> stricter, fewer
detections.

The default config keeps 3x3 NMS on. To disable it (debug only), pass
`useNms=false` to the `FOMOPostProcessing` constructor in `main.cpp`.

## 5. Expected output

On the serial terminal:

```
Set tensor arena cache policy to WTRA
Added ETHOS-U support to op resolver
Model file size 2496160
Initialised model
[fomo] people = 0
[fomo] people = 2
Total inference rate: 50
```

On the LCD: the live camera frame, with the count `people=N` rendered in
red at the top-left and a green box around every active grid cell.

If you see `people = 36` (every cell firing), the input preprocessing is
wrong -- most likely the `pixel - 128` line was deleted or the camera
output is YUV instead of RGB888. Check `ImageSensor_Config(eIMAGE_FMT_RGB565,...)`
and `imlib_nvt_scale(... PIXFORMAT_RGB888)`.
